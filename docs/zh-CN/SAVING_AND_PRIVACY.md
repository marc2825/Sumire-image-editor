# 保存与隐私

汇总了保存的机制、元数据的删除与恢复、管理记录的处理，以及本应用无法防止的情况。

## 保存方式

| 设置 | 行为 |
| --- | --- |
| 覆盖保存原图 | 以相同的位置、名称和格式替换 PNG、JPEG、WebP。替换前的原图会临时保留到应用退出为止（见下文）。其他格式无法覆盖 |
| 保存到其他文件夹 | 以 PNG（默认）、JPEG 或无损 WebP 保存到原图所在文件夹内的 `Sumīre`（可更改）。存在同名文件时添加 `_2` 等 |

- 即使是覆盖，也会先写入临时文件并确认，没有问题后才与原文件替换。失败或取消时，原文件不变。
- 保存前会核对打开时原图的 SHA-256，如果已被其他应用更改或删除，则中止覆盖。
- 保存到其他文件夹的图像，只有由 Sumīre 导出且内容未被更改的文件才会自动更新。
- 开启“临时保留覆盖前的原图”（默认开启）后，会将启动后首次覆盖前的原图复制到系统临时文件夹中的 `sumire-backup-*`。通过“⋯ → 恢复覆盖前的原图”，会在核对内容后恢复原文件。应用退出时删除，因强制结束而残留的部分会在超过 7 天后的下次启动时删除。
- 裁剪、调整尺寸、超分辨率放大也遵循通常的保存方式。覆盖设置下，应用前会确认。覆盖保存并退出后，裁掉的部分无法恢复。
- 另存为、转换格式、压缩体积、创建拼贴和导出已采用只会创建新文件，不会更改原图或正在编辑的图像。

JPEG 以质量 95（可在 1–100 之间更改）、不进行色度抽样的方式保存，透明部分变为白色。JPEG 每次保存都会重新压缩，因此即使未加工的部分也会略有变化。

## 保留元数据的保存

默认情况下，加工后保存也会保留原图的元数据。保存前会读取原图的元数据，并附加到由加工后的像素重新生成的图像上。

- 只有以与原图相同的格式保存时（覆盖，或相同格式的其他文件夹保存）才能附加。格式改变时，会不附加元数据直接保存。
- 方向（Orientation）会应用到像素并设为“1”，ICC 配置文件替换为 sRGB。NovelAI 的 Stealth PNGInfo 会重新嵌入加工后的像素中（JPEG 除外）。
- **不会保留会成为加工前图像副本的内容。** EXIF 缩略图、厂商专有信息（MakerNote，可能包含预览图）、Photoshop 缩略图、嵌入 XMP 或文本中的图像（例如 Google 相机放入 XMP 中的原图）、JFIF 缩略图，以及 MPF、FlashPix、扩展 XMP、C2PA 等段都会排除。EXIF 只去除缩略图和 MakerNote 后重写，日期、相机、位置信息等会保留。
- 只保留可以识别类型的信息：EXIF、GPS、XMP、PNG 文本、注释、IPTC、分辨率等。无法识别的段（例如 PNG 的私有块）不会保留。
- 可通过图像上方的“元数据：有 / 无”确认保存后图像的状态。

## 删除元数据

使用“删除元数据”“批量删除元数据”“删除元数据并保存”，或在开启“保存时删除元数据”的状态下保存时，会仅根据像素重新生成新图像并导出。原图的 EXIF、GPS、XMP、IPTC、注释、PNG 文本（`tEXt`、`zTXt`、`iTXt`、`eXIf`）、生成提示词、软件名称、作者、版权声明、ICC 配置文件和嵌入的缩略图都不会继承。NovelAI、Stable Diffusion、ComfyUI 等添加的信息也同样。

**NovelAI 嵌入像素中的提示词信息（Stealth PNGInfo）也会删除。** 发现 [NovelAI 实现](https://github.com/NovelAI/novelai-image-metadata)的 `stealth_pngcomp`，或[相关方式](https://github.com/neggles/sd-webui-stealth-pnginfo)的 `stealth_pnginfo`、`stealth_rgbcomp`、`stealth_rgbinfo` 时，会清除整个最低有效位区域（不会读取其内容）。

- 在打开图像时（旋转和颜色转换之前）去除，保存时也会确认没有残留。
- 对于 NovelAI 的不透明图像，只会将透明度恢复为 255，颜色和尺寸不变。对于有透明部分的图像或 RGB 方式，相应的颜色最多变化 1 级。
- 用旧版本保存的图像，请用“删除元数据”或“批量删除元数据”重新处理。

保存的图像会重新读取，确认尺寸、格式、单帧，以及没有残留元数据和 Stealth PNGInfo。还会检查文件结构：PNG 只允许 `IHDR`、`IDAT`、`IEND`，JPEG 只允许编码所需的部分和 `JFIF`，WebP 只允许 `VP8`、`VP8L`、`VP8X`、`ALPH`。有问题时会放弃保存。

新文件以不会覆盖已有文件的方式（硬链接）创建。**在 Windows 上建议使用 NTFS 的本地文件夹。** 不支持硬链接的保存位置会保存失败，不会留下不完整的文件。

“元数据：无”表示上述检查没有发现问题。并不保证没有使用未知的嵌入方式。

## 用于恢复的元数据

开启“保存删除前的元数据以便恢复”（默认开启）时，会在改写图像之前，将原元数据用 zlib 压缩后保存到管理记录中。无法保存时，不会改写图像。

- 通过“⋯ → 其他 → 另存带有恢复元数据的副本”，可以生成在当前加工结果上附加了元数据的副本。不会覆盖原图或现有文件。与保留元数据的保存相同，缩略图等会成为加工前图像副本的内容不会恢复（仍保留在管理记录中）。
- 原图为 PNG、JPEG、WebP 时副本保持相同格式，BMP、AVIF、TIFF、GIF 时为 PNG。用转换格式、压缩体积、另存为生成的文件也可以恢复。
- 即使重命名、重新保存或移动管理记录的位置，也可以通过图像的 SHA-256 进行核对和恢复。
- 图像方向设为“1”，颜色统一为 sRGB（原值保留在管理记录中）。Stealth PNGInfo 会恢复头部和正文，不会恢复末尾的纠错数据。结果与原文件不会完全相同。
- 每张解压后最多 16 MiB，总计最多 128 MiB。
- **使用此功能之前删除的信息，或未为恢复而保留的信息无法恢复。**

**压缩并不是加密。** 管理记录中会原样保留删除的提示词、位置信息和嵌入的缩略图。分享图像时，请不要包含管理记录（`.sumire-index.sqlite3` 及其临时文件）。

## 管理记录

保存记录、标签、备注、编辑蒙版和用于恢复的元数据保存在 SQLite 管理记录中。

- 保存在应用专用位置（与设置相同位置的 `records/<每个文件夹的标识符>/`）。不会在图像文件夹中创建，因此即使分享整个文件夹，也不会传出删除的元数据。
- 从 0.4.0 或更早版本开始使用时，为了不丢失记录，会继续保存在图像文件夹内的 `.sumire-index.sqlite3`。Windows 会显示以“.”开头的文件，分享时请注意。
- 在“齿轮 → 管理记录”中切换保存位置时会迁移记录。失败时会恢复原状。
- 在同一界面中可以删除当前列表的记录。图像和编辑项目会保留。

管理记录中保存的是由文件路径生成的标识符、输出的文件名、格式和 SHA-256、是否已编辑、标签、备注、黑白蒙版、变换步骤以及用于恢复的元数据。不包含图像本身、原路径的明文和编辑历史。

设置文件（`sumire-workspace.json`）中包含用于恢复工作的路径、最近使用的文件夹和预设。

## 支持的图像

- 可以打开静态的 PNG、JPEG、WebP、AVIF、BMP、TIFF、GIF。不支持动画、多页 TIFF、SVG、RAW、HEIC（由于许可原因，未附带 HEIC 所需的组件）。
- 超过 2400 万像素、每边 32,768 px 或 256 MiB 的图像，损坏的图像，以及无法转换颜色的图像无法打开。16 位图像会转换为 8 位。
- 打开时会将 EXIF 方向应用到像素，有 ICC 配置文件时转换为 sRGB。不会保留原配置文件，因此在某些环境中颜色看起来可能不同。

## 大量图像

“批量删除元数据”会逐张重新保存标签页中的所有图像（包括已保存的）。执行前会确认张数、保存方式和保存位置。失败的图像会跳过并继续，结束后以列表显示。即使中止，已保存的部分也会保留。

为了控制内存，正在加工的图像每个标签页最多保留最近 2 张（256 MiB），整个应用约 512 MiB。当前图像和未保存的加工不会释放。撤销历史按每张约 80 步或 48 MiB 从最旧的开始删除（最近一步无论大小都会保留）。列表的缩略图仅用于显示，不会用于保存。

## 无法防止的情况

- **不保证马赛克或模糊能完全隐藏。** 需要确实隐藏的部分，请用不透明度 100% 填充，并以原尺寸确认。
- 图像中绘制的文字、可见水印、未知的嵌入方式、文件名、文件夹名、操作系统的历史记录、云同步不在处理范围内。无法完全匿名化。
- 编辑项目（`.sumire`）中包含加工前的图像。

## 临时文件

应用不会将图像或元数据写入日志。工作中会创建以下临时文件，处理结束后删除。因强制结束或停电而残留时，可在退出应用后删除。

| 文件 | 内容 |
| --- | --- |
| `.sumire-*.tmp` | 正在保存的加工后图像 |
| `.sumire-project-*` | 正在保存的编辑项目数据（包含原图） |
| `.sumire-restore-*.tmp` | 正在恢复的带元数据的图像 |
| `.sumire-staging-*` | 转换格式、压缩体积导出前的图像 |
| `sumire-backup-*`（系统临时文件夹） | 覆盖前的原图（应用退出时删除） |
| `.sumire-rename-*.tmp`、`.json` | 重命名过程中保护原图的链接和恢复用记录 |

重命名中途停止时，下次打开该文件夹会恢复原名称或确定更改。发现被替换为其他文件时，会保留恢复用文件并中止。

为防止多个 Sumīre 同时改写同一图像，会在系统临时文件夹的 `sumire-locks-*` 中放置锁文件。由于无法防止其他应用的更改，还会同时核对内容的哈希值。
