# 保存とプライバシー

保存の仕組み、メタデータの削除と復元、管理記録の扱い、そしてこのアプリでは防げないことをまとめています。

## 保存の方法

| 設定 | 動作 |
| --- | --- |
| 元画像に上書き | PNG・JPEG・WebPを、同じ場所・名前・形式で置き換えます。置き換える前の元画像は、アプリを終了するまで一時的に残します（下記）。ほかの形式は上書きできません |
| 別フォルダーに保存 | 元画像のフォルダー内の `Sumīre`（変更可）に、PNG（初期値）・JPEG・可逆WebPで保存します。同じ名前があれば `_2` などを付けます |

- 上書きでも、まず一時ファイルに書いて確かめ、問題がなければ元のファイルと入れ替えます。失敗したときや取り消したときは、元のファイルは変わりません。
- 開いたときの元画像のSHA-256を保存の直前に照合し、ほかのアプリで変更・削除されていれば上書きを中止します。
- 別フォルダーに保存した画像を自動で更新するのは、Sumīreが書き出し、内容が変わっていないファイルだけです。
- 「上書き前の元画像を一時的に残す」（初期状態でオン）では、起動して最初に上書きする直前の元画像を、OSの一時フォルダーの `sumire-backup-*` にコピーして残します。「⋯ → 上書き前の元画像に戻す」で、内容を照合してから元のファイルに戻します。アプリを終了すると削除し、強制終了で残った分は7日を過ぎると次の起動時に削除します。
- 切り抜き・リサイズ・超解像も、通常の保存方法に従います。上書きの設定では、適用前に確認します。上書きして終了すると、切り落とした部分は戻せません。
- 別名保存・形式変換・容量削減・コラージュ・ラベルごとの書き出し（コピー）は、新しいファイルを作るだけで、元画像も作業中の画像も変えません。例外は、容量削減の「元画像に上書きする」（形式が変わらない画像を置き換える）と、ラベルごとの書き出しの「元画像を移動する」（ファイルをそのまま移す）です。

JPEGは品質95（1〜100で変更可）・色の間引きなしで保存し、透過部分は白にします。JPEGは保存のたびに圧縮し直すため、加工していない部分もわずかに変わります。

## メタデータを残す保存

初期設定では、加工して保存しても元画像のメタデータを残します。保存の直前に元画像のメタデータを読み取り、加工後の画素で作り直した画像に付け直します。

- 付け直せるのは、元と同じ形式で保存する場合です（上書き、または同じ形式の別フォルダー保存）。形式が変わる場合は、メタデータを付けずに保存します。
- 向き（Orientation）は画素に反映して「1」に、ICCプロファイルはsRGBに置き換えます。NovelAIのStealth PNGInfoは、加工後の画素に埋め込み直します（JPEGを除く）。
- **加工前の画像の写しになるものは残しません。** EXIFのサムネイル、メーカー独自の情報（MakerNote。プレビュー画像を含むことがあります）、Photoshopのサムネイル、XMPやテキストに埋め込まれた画像（GoogleのカメラがXMPに入れる元画像など）、JFIFのサムネイル、MPF・FlashPix・拡張XMP・C2PAなどの区画は除きます。EXIFは、サムネイルとMakerNoteだけを除いて書き直し、日時・カメラ・位置情報などは残します。
- 残すのは、EXIF・GPS・XMP・PNGのテキスト・コメント・IPTC・解像度など、種類の分かる情報だけです。意味の分からない区画（PNGの独自チャンクなど）は残しません。
- 画像の上の「メタデータ：有り／無し」で、保存した画像の状態を確かめられます。

## メタデータの削除

「メタデータを削除」「メタデータ一括削除」「メタデータを削除して保存」、または「保存するときにメタデータを削除」をオンにした保存では、画素だけから新しい画像を作り直して書き出します。元画像のEXIF・GPS・XMP・IPTC・コメント・PNGのテキスト（`tEXt`・`zTXt`・`iTXt`・`eXIf`）・生成プロンプト・ソフトウェア名・作者・著作権表示・ICCプロファイル・埋め込みサムネイルは引き継ぎません。NovelAI・Stable Diffusion・ComfyUIなどが付ける情報も同じです。

**NovelAIが画素に埋め込むプロンプト情報（Stealth PNGInfo）も消します。** [NovelAIの実装](https://github.com/NovelAI/novelai-image-metadata)の `stealth_pngcomp` と、[関連する方式](https://github.com/neggles/sd-webui-stealth-pnginfo)の `stealth_pnginfo`・`stealth_rgbcomp`・`stealth_rgbinfo` を見つけると、その最下位ビットの領域をすべて取り除きます（内容は読み出しません）。

- 取り除くのは、開いたとき（回転や色の変換より前）です。保存時にも、残っていないことを確かめます。
- NovelAIの不透明な画像は透明度を255に戻すだけで、色と寸法は変わりません。透過のある画像やRGB方式では、該当する色が最大1段階変わります。
- 以前の版で保存した画像は、「メタデータを削除」か「メタデータ一括削除」でもう一度処理してください。

保存した画像は読み直して、寸法・形式・1フレームであること、メタデータとStealth PNGInfoが残っていないことを確かめます。さらにファイルの構造を調べ、PNGは `IHDR`・`IDAT`・`IEND`、JPEGは符号化に必要な部分と `JFIF`、WebPは `VP8`・`VP8L`・`VP8X`・`ALPH` だけを許します。問題があれば保存を取りやめます。

新しいファイルは、既存のファイルを上書きしない方法（ハードリンク）で作ります。**WindowsではNTFSのローカルフォルダーをお勧めします。** ハードリンクを使えない保存先では保存に失敗し、不完全なファイルは残しません。

「メタデータ：無し」は、ここまでの確認で問題がなかったという意味です。未知の埋め込み方法がないことまでは保証しません。

## 復元用のメタデータ

「削除前のメタデータを復元用に保存」（初期設定でオン）では、画像を書き換える前に、元のメタデータをzlibで圧縮して管理記録に保存します。保存できなかったときは、画像を書き換えません。

- 「⋯ → その他 → メタデータを復元して別名保存」で、今の加工結果にメタデータを付けたコピーを作れます。元画像や既存のファイルは上書きしません。サムネイルなど加工前の画像の写しになるものは、メタデータを残す保存と同じく戻しません（管理記録には残っています）。
- 形式は、元がPNG・JPEG・WebPなら同じ形式、BMP・AVIF・TIFF・GIFならPNGです。形式変換・容量削減・別名保存で作ったファイルからも復元できます。
- 名前を変えたり、保存し直したり、管理記録の場所を移したりしても、画像のSHA-256で照合して復元できます。
- 画像の向きは「1」、色はsRGBにそろえます（元の値は管理記録に残ります）。Stealth PNGInfoは見出しと本文を戻し、末尾の誤り訂正データは戻しません。元のファイルとまったく同じにはなりません。
- 1枚あたり展開後16MiB、全体で128MiBまでです。
- **この機能を使う前に消した情報や、復元用に残していない情報は戻せません。**

**圧縮は暗号化ではありません。** 管理記録には、消したプロンプト・位置情報・埋め込みサムネイルがそのまま残ります。画像を共有するときは、管理記録（`.sumire-index.sqlite3` とその一時ファイル）を含めないでください。

## 管理記録

保存の記録・ラベル・メモ・加工マスク・復元用のメタデータは、SQLiteの管理記録に保存します。

- 保存先は、アプリ専用の場所（設定と同じ場所の `records/<フォルダーごとの識別子>/`）です。画像フォルダーには作らないため、フォルダーをまとめて共有しても、消したメタデータは渡りません。
- 0.4.0以前から使っている場合は、記録を見失わないよう、画像フォルダー内の `.sumire-index.sqlite3` のままです。Windowsでは「.」で始まるファイルも表示されるので、共有するときはご注意ください。
- 「歯車 → 管理記録」で保存先を切り替えると、記録を移します。失敗したときは元に戻します。
- 同じ画面で、今の一覧の記録を削除できます。画像と編集プロジェクトは残ります。

管理記録に入れるのは、ファイルのパスから作った識別子、出力のファイル名・形式・SHA-256、編集の有無、ラベル、メモ、白黒のマスク、変形の手順、復元用のメタデータです。画像そのもの、元のパスの平文、編集の履歴は入れません。

設定ファイル（`sumire-workspace.json`）には、再開用のパス、最近使ったフォルダー、プリセットが入ります。

## 扱える画像

- 開けるのは静止画のPNG・JPEG・WebP・AVIF・BMP・TIFF・GIFです。アニメーション、複数ページのTIFF、SVG、RAW、HEICには対応していません（HEICはライセンスの都合で、必要な部品を同梱していません）。
- 2,400万画素・1辺32,768px・256MiBを超える画像、壊れた画像、色を変換できない画像は開けません。16bitの画像は8bitにします。
- 開くときに、EXIFの向きを画素に反映し、ICCプロファイルがあればsRGBに変換します。元のプロファイルは残さないため、環境によって色の見え方が変わることがあります。

## 大量の画像

「メタデータ一括削除」は、保存済みを含むタブ内の全画像を1枚ずつ保存し直します。実行前に、枚数・保存方法・保存先を確認します。失敗した画像は飛ばして続け、終わったら一覧で示します。中止しても、それまでに保存した分は残ります。

メモリーを抑えるため、加工中の画像はタブごとに直近2枚・256MiBまで、アプリ全体で512MiBを目安に保ちます。表示中の画像と未保存の加工は解放しません。元に戻す履歴は、1枚あたり80回・48MiBを目安に古いものから消します（直前の1回は大きさにかかわらず残します）。一覧のサムネイルは表示専用で、保存には使いません。

## 防げないこと

- **モザイクやぼかしで完全に隠せる保証はありません。** 確実に隠す部分は不透明度100%で塗りつぶし、原寸で確かめてください。
- 画像に描かれた文字、見える透かし、未知の埋め込み方法、ファイル名、フォルダー名、OSの履歴、クラウドの同期は対象外です。完全な匿名化はできません。
- 編集プロジェクト（`.sumire`）には、加工前の画像が入っています。

## 一時ファイル

アプリは画像やメタデータをログに出しません。作業中は次の一時ファイルを作り、処理が終われば消します。強制終了や停電で残った場合は、アプリを終了してから削除できます。

| ファイル | 中身 |
| --- | --- |
| `.sumire-*.tmp` | 保存中の加工後の画像 |
| `.sumire-project-*` | 編集プロジェクトの保存中のデータ（元画像を含む） |
| `.sumire-restore-*.tmp` | 復元中の、メタデータ付きの画像 |
| `.sumire-staging-*` | 形式変換・容量削減の書き出し前の画像 |
| `sumire-backup-*`（OSの一時フォルダー） | 上書きする前の元画像（アプリの終了時に削除） |
| `.sumire-rename-*.tmp`・`.json` | 名前の変更中に元画像を守るためのリンクと、復旧用の記録 |

名前の変更が途中で止まった場合は、次にそのフォルダーを開いたときに、元の名前へ戻すか変更を確定します。ほかのファイルへの差し替えを見つけた場合は、復旧用のファイルを残して中止します。

Sumīre同士が同じ画像を同時に書き換えないよう、OSの一時フォルダーの `sumire-locks-*` にロックファイルを置きます。ほかのアプリによる変更は防げないため、内容のハッシュの照合も併せて行います。
